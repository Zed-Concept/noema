# ADR-001: Noema is built by a controller-dispatched multi-agent model with a reviewer of record who never built the unit

**Date:** 2026-08-17
**Status:** Accepted
**Deciders:** Ahmed (owner) and the Noema Controller

> Immutable. Once committed, do not edit this file. To change the decision,
> write a new ADR and set this one's status to Superseded.

## Context

Noema is built almost entirely by AI agents, across several model families, with
one human owner. That arrangement has two failure modes that are worth naming
before they happen rather than after.

The first is **self-review**. A model that just wrote a unit is the worst
available judge of it: it re-reads its own reasoning and finds it persuasive. Any
review lane where the builder can also be the reviewer produces PASS verdicts
that mean nothing.

The second is **collision and drift**. Multiple agents, sessions with no shared
memory, and a chat transcript as the only record of who owns what — that
combination produces two agents editing the same surface, and decisions that get
relitigated because the last session's reasoning was never written down.

Constraints that were real at the time of this decision: one human owner, who is
the sole holder of production credentials and the only party who merges; several
capable model families available concurrently, with genuinely different
strengths; and no repository governance at all — this ADR is written in the same
commit that first creates it.

## Decision

Noema runs a fixed multi-agent operating model with separated roles.

The **controller** is the Noema Controller Claude Project conversation. It issues
dispatches, adjudicates technical disputes, owns the Linear sync, and owns the
controller-only sections of `PROJECT-STATE.md`. It writes no product code. The
**primary builder** is Claude Code at Opus, high effort, with a fresh session per
unit of work. A **secondary builder**, OpenCode GPT-5.6 Terra, is inactive by
default and works only when explicitly dispatched, always on its own branch. The
**reviewer of record** is Codex, with a cross-family flip: if a GPT-family model
built the unit, the RoR becomes a fresh Claude Code review session instead. The
builder never reviews its own unit, and the RoR is named in the LOCK block before
review begins. An **advisory reviewer** — exactly one of Kimi K2.7 Code or
DeepSeek V4 Pro, chosen by the controller, never both — is engaged only for an
architecture freeze, a diff touching auth, RLS, or payments, or a risk the RoR
flags. **Manus** is a read-only investigator on disposable branches with no
credentials and nothing merged; that arrangement is a trial ending 2026-08-25.
`docs/01-state/BRANCH-NOTES.md` is the authoritative lock record, and Linear is a
controller-synced mirror of it: where the two disagree, the repository wins.

## Alternatives considered

| Option | Why not |
|---|---|
| Single agent builds and reviews its own work | The failure mode this ADR exists to prevent. A model reviewing its own output re-reads its own reasoning approvingly; the verdict carries no information. |
| Linear as the authoritative lock record, repo as mirror | Linear is outside the repo. An agent that reads the repo cold cannot see it, and a stale ticket silently authorises a collision. The lock must live where the builder is already looking. |
| Advisory reviewers on every unit | Real cost and real latency for units that carry no architectural or security risk. Gating advisory review behind named triggers keeps it meaningful; reviewing everything trains everyone to skim. |
| Continuous long-lived builder sessions instead of fresh per unit | Context accumulates stale assumptions, and a state file is only load-bearing if sessions actually start from it. Fresh sessions force `PROJECT-STATE.md` to earn its keep. |
| Manus with write access or credentials | Untested tool, no track record in this project, and a live trial window. Read-only on disposable branches is the only version that cannot cost anything. |

## Consequences

This commits the project to writing things down. A LOCK block per unit, an
immutable review record per review, a HANDOFF block per session. That is real
overhead on small units, and it is accepted: the alternative is unrecoverable
ambiguity about who owns what.

It also commits to a slower pipeline. Nothing merges without a review by a
different model in a fresh session, and the owner merges. Some units will wait on
the reviewer of record; that latency is the price of the review meaning
something.

Two items land in constrained lanes as a direct consequence. Diffs touching
**auth, RLS, or payments** mandatorily trigger advisory review — this compounds
with those areas already being RED lane in `AGENTS.md`, so such work needs both
explicit approval to start and a second reviewer to land. And the Manus trial has
a hard expiry of **2026-08-25**; past that date, continuing to use Manus requires
a new decision on the record, not silent continuation.

This decision is recorded as **binding ruling #1** in
`docs/01-state/PROJECT-STATE.md` in the same commit.
