# ADR-008: The persistence-failure surfacing guarantee is native-only

**Date:** 2026-08-25
**Status:** Accepted
**Deciders:** CTRL-005 controller, under ruling 19 (overclaim correction is
controller-class); owner notified

> Immutable. Once committed, do not edit this file. To change the decision,
> write a new ADR and set this one's status to Superseded.

## Relationship to ADR-007

This ADR narrows exactly one sentence of ADR-007:

> **A refresh whose persistence fails is surfaced, not silently dropped.**

ADR-007's other decisions stand unchanged: `autoRefreshToken: false`, refresh
initiated only by explicit foreground-gated calls, and locked-device behaviour
NOT RUN / NOT CLAIMED in Phase A with a named Phase B device test. ADR-007's
status remains `Accepted` and its file is not edited — ruling 16.

## Context

REVIEW-021-ADVISORY, the first firing of the ADR-001 advisory seat, found that
the sentence above is platform-unqualified while the mechanism enforcing it is
not. The write observer wraps the module-scope SecureStore-backed adapter handed
to the client. On web, storage is `localStorage` through the `supabase-js`
default; that path never reaches the adapter, so no observer exists and no flag
is set.

The advisory also established why the mechanism is otherwise strong, and that
part is worth preserving in the record: detection sits **at the write, not at
the initiator**, so every failing `setItem` — gated refresh, bootstrap refresh,
listener-emission refresh, `verifyOtp` persist — sets the flag before rethrowing,
and the flag survives auth-js's own error handling. Even a swallowed rejection
leaves it set. That property is what makes the ungated-entrance defect
survivable on native rather than fatal.

The same advisory confirmed the remedy's shape should survive: forced
re-authentication is proportionate and not remotely inducible, since the trigger
is strictly store refusal, local sign-out scope is preserved, and the
alternative outcome — refresh-token reuse detection revoking the family — is
strictly worse.

## Decision

The surfacing guarantee holds **on native only**. No unqualified cross-platform
claim of surfacing may be made in code comments, evidence, documentation, or
product copy. Web surfacing is **deferred and named, not claimed**: `localStorage`
write failure is rare but real — quota exhaustion and private-browsing modes —
and a web observer is recorded to the backlog as a named future unit rather than
left implicit.

## Alternatives considered

| Option | Why not |
|---|---|
| Build a web observer so the sentence becomes true everywhere | Puts additional code on the auth path — the position ADR-004 identifies as the highest-risk in the repo — during the final fix cycle of a unit that needs to close, for a failure mode that is rare on web and has no capture loop behind it yet. Deferred, not rejected on the merits. |
| Leave ADR-007's sentence unqualified and treat the gap as a documentation note | An immutable record cannot be amended by commentary elsewhere; REVIEW-020 finding 5 already settled that against a README disclosure. The sentence would remain a claim the architecture does not enforce. |
| Restate the whole of ADR-007 | Would falsely retire decisions the reviews confirmed sound. Ruling 16 exists for exactly this. |

## Consequences

- Evidence and code must state the platform boundary wherever surfacing is
  claimed. An unqualified sentence is a defect, not a simplification.
- Web keeps `localStorage` per ADR-004 and gains no new guarantee here. The
  platform split now runs consistently through storage (ADR-004), read
  integrity (ADR-006), and surfacing (this ADR).
- A web write observer is a named backlog unit.
- Recorded as binding ruling 18. Ruling 19 records that this correction class is
  controller-owned; the owner was notified rather than asked, and may supersede.
- This is the client auth surface; every future change to it remains RED lane.
