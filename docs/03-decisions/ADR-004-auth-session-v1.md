# ADR-004: v1 authenticates by email one-time code, over encrypted chunked session storage

**Date:** 2026-08-24
**Status:** Accepted
**Deciders:** Ahmed (owner); CTRL-005 controller

> Immutable. Once committed, do not edit this file. To change the decision,
> write a new ADR and set this one's status to Superseded.

## Context

Unit C made `auth.uid()` the authorization boundary for every row in the
database. Nothing can be captured until a client can establish who the user is,
so the auth method had to be settled before the L0 capture loop could begin.

The constraint that decided it is ruling 8. `expo.scheme` is frozen pending
trademark clearance, and every redirect-based flow needs a scheme. The
non-obvious consequence is that the freeze does not merely defer OAuth: it also
removes **password recovery**, because `resetPasswordForEmail` sends a redirect
link. Email-plus-password is therefore not the simple option it appears to be —
it requires shipping one-time-code machinery anyway, for recovery, and then
adds a password surface on top of it.

Against that sits principle 2 (zero-friction capture) and principle 4 (privacy
is structural — only claims the architecture actually enforces are ever made).
Principle 4 is what makes token storage a decision rather than a default:
`expo-secure-store` writes to the iOS Keychain and Android Keystore but caps
per-value size below what a Supabase session commonly occupies, while
`AsyncStorage` has no cap and no encryption.

## Decision

v1 authenticates by **email one-time code**: `signInWithOtp` with
`shouldCreateUser: true`, then `verifyOtp` with `type: 'email'`. There is no
password anywhere in the product, and no `emailRedirectTo` on any call. The
session is persisted through a **SecureStore-backed chunking adapter** that
handles the session as an opaque string and never mints, parses, validates, or
refreshes a token. Chunk keys derive deterministically from the base key; a
partial or corrupt read **fails closed to null** rather than handing a
truncated string to `supabase-js`; removal clears every chunk and the index.
Web keeps the `supabase-js` `localStorage` default, and the platform split is
explicit in code rather than implicit.

## Alternatives considered

| Option | Why not |
|---|---|
| Email + password | Recovery needs a redirect link, blocked by ruling 8. One-time-code machinery ships regardless, so this is strictly more code and more attack surface for no gain. This was the option nearly chosen, on the assumption it was the simplest. |
| Magic link, or native Apple/Google OAuth | Both require `expo.scheme`, frozen by ruling 8. Revisit after trademark clearance; this ADR does not foreclose them. |
| Anonymous session first, upgrade on demand | Best on principle 2, and the Unit C provisioning trigger already fires for anonymous users. But it adds an account-linking path plus unauthenticated user creation writing `profiles` rows — a wider security surface on the very first auth unit, spent optimising friction on a screen with no capture loop behind it yet. Recorded to the backlog as a named future unit rather than discarded. |
| `AsyncStorage` for session tokens | No size ceiling, no encryption. Tokens readable on a rooted device or through backup extraction, which would make a structural-privacy claim the architecture does not enforce. |
| Hybrid — refresh token in SecureStore, remainder in `AsyncStorage` | Two stores to keep consistent on the auth path; the failure mode is a split session, which is harder to reason about than chunking. |

## Consequences

- Every sign-in costs an inbox round trip. In exchange there is no password to
  store, reset, leak, or reuse, and no recovery flow to build.
- The chunking adapter is **custom code on the auth path**, which is the
  highest-risk placement in the codebase. The constraints above exist to bound
  it, and they are review-gated properties, not style preferences. Its
  correctness is testable without credentials, and that is where its strongest
  evidence must sit.
- **On web, tokens are in `localStorage`.** There is no secure browser store.
  No product or marketing claim about token storage may be made without a
  platform qualifier. Not enforced on web, therefore not claimed.
- Staging posture is owner-executed: confirm-email off permanently, plus a
  ruled test-address domain. Supabase's default email rate limits will bind
  during live evidence and must be planned around, not discovered.
- Adds one dependency, `expo-secure-store`, and its config plugin.
  `expo.scheme` is untouched and stays frozen.
- This is the client authentication surface, so **every future change to it is
  RED lane** per AGENTS.md. Recorded as binding ruling 12 in `PROJECT-STATE.md`
  in this same commit.
