# ADR-005: Sign-out is device-local and token refresh is foreground-gated

**Date:** 2026-08-24
**Status:** Accepted
**Deciders:** Ahmed (owner); CTRL-005 controller

> Immutable. Once committed, do not edit this file. To change the decision,
> write a new ADR and set this one's status to Superseded.

## Context

Two inherited defaults surfaced as adjacent findings during Unit D. The builder
reported both and correctly acted on neither, since each changes security
posture.

First, `auth-js` defaults `signOut()` to `scope: 'global'`. Signing out on a
phone therefore destroys the same user's session on their tablet, silently.

Second, `expo-secure-store` defaults to `WHEN_UNLOCKED` accessibility, so a
background token refresh on a locked device cannot write. The rotated token is
lost, the next unlock presents a superseded refresh token, and Supabase's
refresh-token reuse detection can revoke the whole family and sign the user
out. The failure is silent, device-dependent, and would arrive as an
unreproducible bug report.

ADR-004 chose SecureStore specifically on principle 4, which constrains the
remedy: any fix that weakens at-rest protection would undo the reasoning that
selected the store in the first place.

## Decision

`signOut()` passes `scope: 'local'`. Token auto-refresh is **gated on
AppState** — `startAutoRefresh` when the app is active, `stopAutoRefresh` when
it is backgrounded or inactive — so a refresh only ever fires while the app is
foreground and the device therefore unlocked. SecureStore keeps `WHEN_UNLOCKED`.

## Alternatives considered

| Option | Why not |
|---|---|
| Keep `scope: 'global'` | A routine sign-out on one device silently destroys sessions everywhere. Surprising and destructive in a multi-device second brain, and it is the wrong default for the common case in order to serve the rare one. |
| `AFTER_FIRST_UNLOCK` accessibility | Solves the lost write by making the session readable while the device is locked after first boot unlock. This genuinely weakens at-rest protection and contradicts the principle-4 reasoning that chose SecureStore in ADR-004. It was the nearly-chosen option, because it is a one-line change. |
| Leave both as inherited defaults | Yields silent cross-device sign-out and a token-loss path terminating in reuse-detection sign-out. Both are user-visible failures with no diagnostic trail. |

## Consequences

- **There is no remote revocation until a "sign out everywhere" affordance
  exists.** A lost device's refresh token stays valid until expiry. This is the
  accepted cost of local scope, and it is the reason the affordance is recorded
  to the backlog as a named v1.x unit rather than left implicit.
- A long-backgrounded session may need a refresh on resume. The bootstrap path
  already handles this through `getSession()`, so no new surface is required.
- **Neither is implemented in the Unit D review candidate.** Both land in the
  post-REVIEW-019 fix cycle; the review dispatch carries them as ruled-pending
  so the reviewer of record reviews with full knowledge and can dissent on the
  record.
- Both are auth-surface changes and therefore RED lane. Recorded as binding
  ruling 13 in `PROJECT-STATE.md` in this same commit.
